# Phase 1.9: Check Alien Commits

**Goal:** Detect and handle commits on `origin/main` that cannot be traced to any known patch branch, preventing unintended history loss during sync operations.

**Status:** Planned

**Related Phases:**

- Depends on Phase 1.4 (Atomic Update) for ref update logic
- Depends on Phase 1.7 (Dry-Run and Status) for preview functionality
- Related to Phase 3.1 (Backport Command) for recovery workflows

## Overview

### The Problem

When `patchstack sync` runs, it rebuilds `origin/main` from scratch:

```
new main = upstream/main + squash(patch-A) + squash(patch-B) + ...
```

This means any commits on `origin/main` that aren't part of this formula will be **lost**. These "alien commits" can appear from:

1. **Direct commits to main** - Someone pushed directly to `origin/main`
2. **Manual merges** - PRs merged directly to main instead of as patch branches
3. **Hotfixes** - Emergency fixes applied directly to main
4. **Migration artifacts** - Commits from before patchstack was adopted
5. **Failed sync recovery** - Manual interventions after failed syncs

### Terminology

- **Alien commit**: A commit on `origin/main` that cannot be traced to:
  - The current `upstream/main` history
  - Any squash commit from a known patch branch
- **Identifiable commit**: A commit that either:
  - Is an ancestor of `upstream/main`
  - Has a patch reference in its commit message (e.g., `[patch-feature]`)
  - Is recorded in `refs/notes/patchstack` as originating from a sync

### Safety Principle

Patchstack should **never silently discard commits**. If alien commits exist:

- In `--dry-run` mode: Show what would be lost with `--delete`
- In normal mode: **Abort** unless `--delete` flag is provided
- Always provide tools to review and recover

## Part 1: Commit Identification via Trailers

### Patch Reference in Commit Messages

Following conventions from tools like **Quilt** and **StGit**, patchstack should add a machine-readable reference to each squash commit:

```
Squash of 3 commits from origin/patch-feature-auth

This commit was auto-generated by patchstack.

<original commit messages here>

---
Patchstack-Patch: patch-feature-auth
```

The `Patchstack-Patch:` trailer:

- Uniquely identifies which patch branch produced this commit
- Survives rebases and cherry-picks (unlike notes)
- Is human-readable and grep-able
- Follows Git trailer conventions (like `Signed-off-by:`)

## Part 2: Alien Commit Detection

### Function: `find_alien_commits()`

Identifies commits on `origin/main` that don't belong:

```bash
find_alien_commits() {
    local origin_main="refs/remotes/$PATCH_REMOTE/$MAIN_BRANCH"
    local upstream_main="refs/remotes/$UPSTREAM_REMOTE/$MAIN_BRANCH"

    # Get all commits on origin/main that aren't in upstream/main
    local fork_commits
    fork_commits=$(git rev-list "$upstream_main..$origin_main")

    local alien_commits=()

    for commit in $fork_commits; do
        if ! is_identifiable_commit "$commit"; then
            alien_commits+=("$commit")
        fi
    done

    # Output alien commits (oldest first)
    printf '%s\n' "${alien_commits[@]}" | tac
}

is_identifiable_commit() {
    local commit=$1

    # Check 1: Does commit have a Patchstack-Patch trailer?
    local trailer
    trailer=$(git log -1 --format='%(trailers:key=Patchstack-Patch,valueonly)' "$commit" 2>/dev/null || true)
    if [[ -n "$trailer" ]]; then
        return 0  # Identifiable: has patch trailer
    fi

    # Check 2: Is this commit recorded in patchstack notes?
    local note
    note=$(git notes --ref=patchstack show "$commit" 2>/dev/null || true)
    if [[ -n "$note" ]] && echo "$note" | grep -q "Patchstack sync"; then
        return 0  # Identifiable: has patchstack note
    fi

    # Check 3: Check for legacy formats (for migration)
    # Look for "Squash: patch-*" in commit message (old format)
    local msg
    msg=$(git log -1 --format='%s' "$commit")
    if [[ "$msg" =~ ^Squash:\ (patch-[a-zA-Z0-9_-]+) ]]; then
        return 0  # Identifiable: legacy format
    fi

    return 1  # Alien: not identifiable
}
```

### Function: `format_alien_commits_report()`

Creates a human-readable report:

```bash
format_alien_commits_report() {
    local -n commits=$1
    local count=${#commits[@]}

    if [[ $count -eq 0 ]]; then
        return 0
    fi

    echo "WARNING: Found $count alien commit(s) on origin/main"
    echo
    echo "These commits cannot be traced to any patch branch and will"
    echo "be REMOVED if you run 'patchstack sync --delete':"
    echo

    for commit in "${commits[@]}"; do
        local short_sha
        short_sha=$(git rev-parse --short "$commit")
        local subject
        subject=$(git log -1 --format='%s' "$commit")
        local author
        author=$(git log -1 --format='%an' "$commit")
        local date
        date=$(git log -1 --format='%cr' "$commit")

        echo "  $short_sha $subject"
        echo "           Author: $author, $date"
    done

    echo
}
```

## Part 3: Flag Handling

### New Flags

Add two new flags to control alien commit behavior:

- `--delete`: Allow sync to proceed even with alien commits (they will be lost)
- `--dry-run --delete`: Show what commits would be deleted (preview mode)

### Updated Flag Parsing

```bash
# Global flags
DRY_RUN=false
DELETE_ALIEN=false

parse_flags() {
    while [[ $# -gt 0 ]]; do
        case "$1" in
            --dry-run)
                DRY_RUN=true
                shift
                ;;
            --delete)
                DELETE_ALIEN=true
                shift
                ;;
            --verbose|-v)
                VERBOSE=true
                shift
                ;;
            *)
                # Not a flag, return remaining args
                REMAINING_ARGS+=("$1")
                shift
                ;;
        esac
    done
}
```

### Updated `cmd_sync()`

```bash
cmd_sync() {
    # ... existing pre-flight checks ...

    # Check for alien commits BEFORE any modifications
    echo "Checking for alien commits..."
    local alien_commits
    readarray -t alien_commits < <(find_alien_commits)

    if [[ ${#alien_commits[@]} -gt 0 ]]; then
        format_alien_commits_report alien_commits

        if [[ "$DRY_RUN" == true ]]; then
            if [[ "$DELETE_ALIEN" == true ]]; then
                echo "DRY RUN with --delete: These commits would be removed."
                echo
            else
                echo "Use 'patchstack sync --dry-run --delete' to preview deletion."
                echo "Use 'patchstack sync --delete' to proceed with deletion."
                echo
            fi
            # Continue with dry-run to show full preview
        else
            # Real run - abort unless --delete specified
            if [[ "$DELETE_ALIEN" != true ]]; then
                echo "ABORTING: Alien commits detected."
                echo
                echo "To review the commits:"
                echo "  patchstack history"
                echo
                echo "To proceed with deletion:"
                echo "  patchstack sync --delete"
                echo
                echo "To preview what would be deleted:"
                echo "  patchstack sync --dry-run --delete"
                echo
                return 1
            fi
            echo "Proceeding with --delete: Alien commits will be removed."
            echo
        fi
    else
        verbose_echo "No alien commits found on origin/main"
    fi

    # ... rest of sync logic ...
}
```

## Part 4: History Review Commands

### Command: `patchstack history`

Shows the full history of `origin/main` with commit provenance:

```bash
cmd_history() {
    local origin_main="refs/remotes/$PATCH_REMOTE/$MAIN_BRANCH"
    local upstream_main="refs/remotes/$UPSTREAM_REMOTE/$MAIN_BRANCH"

    echo "History of $PATCH_REMOTE/$MAIN_BRANCH"
    echo "======================================"
    echo

    # Show commits from upstream to origin/main
    local commits
    commits=$(git rev-list --reverse "$upstream_main..$origin_main")

    if [[ -z "$commits" ]]; then
        echo "Fork main is at same commit as upstream main."
        echo "No patch commits to show."
        return 0
    fi

    echo "Commits above upstream/main:"
    echo

    for commit in $commits; do
        local short_sha
        short_sha=$(git rev-parse --short "$commit")
        local subject
        subject=$(git log -1 --format='%s' "$commit")

        # Determine provenance
        local provenance="???"
        local trailer
        trailer=$(git log -1 --format='%(trailers:key=Patchstack-Patch,valueonly)' "$commit" 2>/dev/null || true)

        if [[ -n "$trailer" ]]; then
            provenance="patch: $trailer"
        else
            local note
            note=$(git notes --ref=patchstack show "$commit" 2>/dev/null || true)
            if [[ -n "$note" ]]; then
                local branch_from_note
                branch_from_note=$(echo "$note" | grep "^Branch:" | cut -d' ' -f2-)
                if [[ -n "$branch_from_note" ]]; then
                    provenance="patch: $branch_from_note (from notes)"
                fi
            else
                # Check for legacy format
                if [[ "$subject" =~ ^Squash:\ (patch-[a-zA-Z0-9_-]+) ]]; then
                    provenance="patch: ${BASH_REMATCH[1]} (legacy)"
                else
                    provenance="ALIEN"
                fi
            fi
        fi

        # Color alien commits
        if [[ "$provenance" == "ALIEN" ]]; then
            echo "  ! $short_sha $subject"
            echo "              [$provenance]"
        else
            echo "  ✓ $short_sha $subject"
            echo "              [$provenance]"
        fi
    done

    echo
    echo "Legend:"
    echo "  ✓ = Traceable to patch branch"
    echo "  ! = ALIEN (not traceable, will be lost on sync)"
}
```

### Command: `patchstack patch-history <branch>`

Shows the sync history of a specific patch branch from notes:

```bash
cmd_patch_history() {
    local branch_name=$1

    if [[ -z "$branch_name" ]]; then
        echo "Usage: patchstack patch-history <branch-name>"
        return 1
    fi

    echo "Sync history for $branch_name"
    echo "=============================="
    echo

    # Find all notes that reference this branch
    local notes_ref="refs/notes/patchstack"

    if ! git rev-parse "$notes_ref" &>/dev/null; then
        echo "No patchstack notes found."
        return 0
    fi

    # Get all commits with notes
    local noted_commits
    noted_commits=$(git notes --ref=patchstack list 2>/dev/null | cut -d' ' -f2)

    local found=0
    for commit in $noted_commits; do
        local note
        note=$(git notes --ref=patchstack show "$commit" 2>/dev/null || true)

        if echo "$note" | grep -q "Branch: $branch_name"; then
            ((found++))
            local short_sha
            short_sha=$(git rev-parse --short "$commit")

            echo "Commit: $short_sha"
            echo "$note" | sed 's/^/  /'
            echo
        fi
    done

    if [[ $found -eq 0 ]]; then
        echo "No sync history found for branch: $branch_name"
    fi
}
```

## Part 7: Migration Considerations

### Handling Existing Forks

When adopting patchstack on an existing fork:

1. **Initial state analysis:**

   ```bash
   patchstack history  # Shows all commits, marks unknowns as ALIEN
   ```

2. **One-time migration options:**
   - `patchstack sync --delete` to accept loss of untracked commits
   - Manual conversion of aliens to patch branches (see Phase 3.1)
   - Add notes manually to "claim" existing commits

3. **Legacy format support:**
   - Detect `Squash: patch-*` format from older versions
   - Accept commits with patchstack notes as identifiable
   - Gradually migrate to trailer format

## Summary

Phase 1.9 adds critical safety features:

1. **Commit tracing:** `Patchstack-Patch:` trailers identify patch origins
2. **Alien detection:** Find commits that would be lost during sync
3. **Safe defaults:** Abort sync if aliens detected (require explicit `--delete`)
4. **Preview mode:** `--dry-run --delete` shows what would be removed
5. **History commands:** Review provenance of all commits on main
6. **Migration path:** Support legacy formats and gradual adoption

This phase ensures patchstack never silently discards user commits, maintaining trust and enabling recovery workflows (Phase 3.1).
